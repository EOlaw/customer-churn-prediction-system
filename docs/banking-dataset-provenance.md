# Banking dataset provenance and permitted use

## Status in this repository

| Dataset | Source kind | Present locally | Analyzed |
| --- | --- | --- | --- |
| `data/raw/banking-demo-synthetic.csv` (generated by `scripts/make_demo_data.py`, fixed seed, IDs prefixed `DEMO-`) | `synthetic` | yes (gitignored) | yes |
| Public "Churn Modelling" CSV | `external` | **no** | **no** |

No real or third-party banking data has been analyzed, trained on, or committed. Every number this repository currently reports (class balance, segment rates, correlations, model metrics) comes from synthetic data whose outcome was generated from a hand-written formula. It demonstrates that the pipeline works and says nothing about real customers. EDA output for it lives in a directory named `eda-synthetic-<hash>` and every table carries `source_kind=synthetic`.

## About the public CSV

The contract targets the widely redistributed Churn Modelling file (see the link in the README). Before using any copy, the importer must establish and record, outside this repository's code:

- where the copy came from and under what licence or terms it may be used for this purpose (the repository cannot verify this; copies circulate with differing documentation);
- whether it describes real customers, and if so the lawful basis and any restrictions on use, since fields such as `Geography`, `Gender`, and `Age` are sensitive in credit-adjacent settings;
- that the contract version in the quality report matches what you intend to analyze.

Do not infer that the data are real, representative, or even of a single bank from this repository. The file is cross-sectional with no dates (see the [leakage review](banking-leakage-review.md)).

## Importing an approved real CSV

```bash
# 1. Place the file (gitignored directory), then validate. Fix the source file if this fails.
cp ~/Downloads/Churn_Modelling.csv data/raw/churn-modelling.csv
python -m churn.ml.data data/raw/churn-modelling.csv --source-kind external --output reports/quality-external.json

# 2. Reproducible EDA (written to reports/eda-external-<hash>/)
python -m churn.ml.eda data/raw/churn-modelling.csv --source-kind external

# 3. Train, import, register, score — the SAME file and the SAME --source-kind throughout
python -m churn.ml.train data/raw/churn-modelling.csv --source-kind external
python -m churn.cli init-db
python -m churn.cli import data/raw/churn-modelling.csv --source-kind external --organization "Approved research"
python -m churn.cli register artifacts/<report printed by training>.json --organization "Approved research"
python -m churn.cli score-all --organization "Approved research"
```

Use a different organization name from the synthetic demo so the two never mix on the dashboard (`ORGANIZATION_NAME` selects the organization the API serves). The same bytes cannot be imported once as synthetic and again as external. Record the dataset SHA-256 and source in your own provenance log next to the approval.
